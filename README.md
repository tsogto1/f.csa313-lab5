## Даалгавар 2: Тест дизайн (Лекц 5-ын 5 алхам)

### Алхам 1. Бие даан тестлэгдэх функц

`POST /registrations` — "хичээлд бүртгүүлэх". Оролт нь `studentID`, `courseID`; гаралт нь статус код ба `result` утга. Оюутан, хичээлийн мэдээллийг өмнө нь `PUT /students/:id`, `PUT /courses/:id` хүсэлтээр бэлдэнэ (setup).

### Алхам 2. Сонголтууд (choices)

| № | Сонголт | Тайлбар |
|---|---------|---------|
| C1 | Оюутны төлөв (studentID-гийн хүчинтэй байдал) | Бичлэг байгаа эсэх, `status` нь "active" эсэх |
| C2 | Оюутны үзсэн хичээлүүд (`coursesTaken`) | Хичээлийн урьдач нөхцөлтэй харьцуулахад хангаж байна уу |
| C3 | Хичээлийн төлөв (courseID-гийн хүчинтэй байдал) | Бичлэг байгаа эсэх |
| C4 | Хичээлийн урьдач нөхцөл (`prerequisites`) | Хоосон / бүгд үзсэн / зарим нь үзсэн / огт үзээгүй |
| C5 | Хүсэлтийн формат | JSON зөв эсэх, шаардлагатай талбарууд байгаа эсэх |

### Алхам 3. Эквивалент анги ба төлөөлөх утгууд

| Сонголт | Анги | Төлөөлөх утга |
|---------|------|---------------|
| C1 | Идэвхтэй оюутан | `B231234567`, `status: "active"` |
| C1 | Идэвхгүй оюутан | `B231234568`, `status: "inactive"` |
| C1 | Байхгүй оюутан | `B999999999` (PUT хийхгүй) |
| C3 | Байгаа хичээл | `CS313` |
| C3 | Байхгүй хичээл | `XX999` (PUT хийхгүй) |
| C4 | Урьдач нөхцөлгүй | `prerequisites: []` |
| C4 | Нэг урьдачтай | `prerequisites: ["CS201"]` |
| C4 | Хоёр урьдачтай | `prerequisites: ["CS201","CS202"]` |
| C2 (C4-тэй хамт) | Бүгдийг хангасан | `coursesTaken: ["CS201"]` ↔ `["CS201"]` |
| C2 (C4-тэй хамт) | Зарим нь дутуу | `coursesTaken: ["CS201"]` ↔ `["CS201","CS202"]` |
| C2 (C4-тэй хамт) | Огт үзээгүй | `coursesTaken: []` ↔ `["CS201"]` |
| C5 | Бүрэн, зөв JSON | `{"studentID":"..","courseID":".."}` |
| C5 | `studentID` дутуу | `{"courseID":"CS313"}` |
| C5 | `courseID` дутуу | `{"studentID":"B231234567"}` |
| C5 | Буруу JSON | `{"studentID": ` |

**Боломжгүй (утгагүй) хослолууд:**
- Оюутан байхгүй үед `coursesTaken` гэж байхгүй, тиймээс C1=байхгүй × C2 хослол утгагүй.
- Хичээл байхгүй үед `prerequisites` гэж байхгүй, тиймээс C3=байхгүй × C4 хослол утгагүй.
- `prerequisites: []` үед "зарим нь дутуу" / "огт үзээгүй" боломжгүй (хангах зүйл байхгүй).
- C5-ийн формат буруу (талбар дутуу, буруу JSON) үед C1–C4 хослол шалгагдах үе шатанд хүрэхгүй.

### Алхам 4. Спецификацууд

| ID | Төрөл | Нөхцөл (setup) | Хүсэлт (POST /registrations) | Хүлээгдэх статус | Хүлээгдэх `result` |
|----|-------|----------------|------------------------------|------------------|--------------------|
| S1 | Happy path | Идэвхтэй оюутан, `coursesTaken:["CS201"]`; `CS313` урьдач `["CS201"]` | `B231234567` → `CS313` | 201 | `OK` (+ `registrationID` тоо) |
| S2 | Алдаа: оюутан байхгүй | `CS313` байгаа; `B999999999` үүсгээгүй | `B999999999` → `CS313` | 200 | `ERROR_NO_STUDENT` |
| S3 | Алдаа: идэвхгүй оюутан | `status:"inactive"`, `coursesTaken:["CS201"]`; `CS313` урьдач `["CS201"]` | `B231234568` → `CS313` | 200 | `ERROR_INACTIVE_STUDENT` |
| S4 | Алдаа: хичээл байхгүй | Идэвхтэй оюутан байгаа; `XX999` үүсгээгүй | `B231234567` → `XX999` | 200 | `ERROR_NO_COURSE` |
| S5 | Алдаа: урьдач нөхцөл (огт үзээгүй) | Идэвхтэй оюутан, `coursesTaken:[]`; `CS313` урьдач `["CS201"]` | `B231234567` → `CS313` | 200 | `ERROR_PREREQUISITES`, `missing:["CS201"]` |
| S6 | Алдаа: урьдач нөхцөл (зарим нь дутуу) | Идэвхтэй оюутан, `coursesTaken:["CS201"]`; `CS314` урьдач `["CS201","CS202"]` | `B231234567` → `CS314` | 200 | `ERROR_PREREQUISITES`, `missing:["CS202"]` |
| S7 | Хязгаар: урьдач нөхцөлгүй хичээл, хоосон `coursesTaken` | Идэвхтэй оюутан, `coursesTaken:[]`; `CS101` урьдач `[]` | `B231234567` → `CS101` | 201 | `OK` |
| S8 | Хязгаар: `studentID` дутуу | — | `{"courseID":"CS313"}` | 400 | `ERROR_BAD_REQUEST` |
| S9 | Хязгаар: `courseID` дутуу | — | `{"studentID":"B231234567"}` | 400 | `ERROR_BAD_REQUEST` |
| S10 | Хязгаар: буруу JSON | — | `{"studentID": ` (хаагдаагүй JSON) | 400 | `ERROR_BAD_JSON` |
| S11 | Давхар алдаа: оюутан ба хичээл хоёулаа байхгүй | Аль нь ч үүсгээгүй | `B999999999` → `XX999` | 200 | `ERROR_NO_STUDENT` (бодит серверээр баталгаажсан: оюутныг хичээлээс өмнө шалгадаг) |
| S12 | Давхар алдаа: идэвхгүй оюутан + урьдач нөхцөл дутуу | `status:"inactive"`, `coursesTaken:[]`; `CS313` урьдач `["CS201"]` | `B231234568` → `CS313` | 200 | `ERROR_INACTIVE_STUDENT` (бодит серверээр баталгаажсан: идэвхгүй эсэхийг урьдач нөхцөлөөс өмнө шалгадаг) |

> S11, S12-ын хүлээгдэх утгыг заавар заагаагүй тул серверт curl-ээр шалгаж тогтоосон. Үр дүнгээс харахад S11-д оюутны алдаа хичээлийн алдаанаас, S12-т идэвхгүй байдлын алдаа урьдач нөхцөлийн алдаанаас түрүүлж буцсан.
