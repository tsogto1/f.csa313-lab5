## Даалгавар 2: Тест дизайн (Лекц 5-ын 5 алхам)

### Алхам 1. Бие даан тестлэгдэх функц

`POST /registrations` — "хичээлд бүртгүүлэх". Оролт нь `studentID`, `courseID`; гаралт нь статус код ба `result` утга. Оюутан, хичээлийн мэдээллийг өмнө нь `PUT /students/:id`, `PUT /courses/:id` хүсэлтээр бэлдэнэ (setup).

### Алхам 2. Сонголтууд (choices)

| № | Сонголт | Тайлбар |
|---|---------|---------|
| C1 | Оюутны төлөв (studentID-гийн хүчинтэй байдал) | Бичлэг байгаа эсэх, `status` нь "active" эсэх |
| C2 | Оюутны үзсэн хичээлүүд (`coursesTaken`) | Хичээлийн урьдач нөхцөлтэй харьцуулахад хангаж байна уу |
| C3 | Хичээлийн төлөв (courseID-гийн хүчинтэй байдал) | Бичлэг байгаа эсэх |
| C4 | Хичээлийн урьдач нөхцөл (`prerequisites`) | Хоосон / бүгд үзсэн / зарим нь үзсэн / огт үзээгүй |
| C5 | Хүсэлтийн формат | JSON зөв эсэх, шаардлагатай талбарууд байгаа эсэх |

### Алхам 3. Эквивалент анги ба төлөөлөх утгууд

| Сонголт | Анги | Төлөөлөх утга |
|---------|------|---------------|
| C1 | Идэвхтэй оюутан | `B231234567`, `status: "active"` |
| C1 | Идэвхгүй оюутан | `B231234568`, `status: "inactive"` |
| C1 | Байхгүй оюутан | `B999999999` (PUT хийхгүй) |
| C3 | Байгаа хичээл | `CS313` |
| C3 | Байхгүй хичээл | `XX999` (PUT хийхгүй) |
| C4 | Урьдач нөхцөлгүй | `prerequisites: []` |
| C4 | Нэг урьдачтай | `prerequisites: ["CS201"]` |
| C4 | Хоёр урьдачтай | `prerequisites: ["CS201","CS202"]` |
| C2 (C4-тэй хамт) | Бүгдийг хангасан | `coursesTaken: ["CS201"]` ↔ `["CS201"]` |
| C2 (C4-тэй хамт) | Зарим нь дутуу | `coursesTaken: ["CS201"]` ↔ `["CS201","CS202"]` |
| C2 (C4-тэй хамт) | Огт үзээгүй | `coursesTaken: []` ↔ `["CS201"]` |
| C5 | Бүрэн, зөв JSON | `{"studentID":"..","courseID":".."}` |
| C5 | `studentID` дутуу | `{"courseID":"CS313"}` |
| C5 | `courseID` дутуу | `{"studentID":"B231234567"}` |
| C5 | Буруу JSON | `{"studentID": ` |

**Боломжгүй (утгагүй) хослолууд:**
- Оюутан байхгүй үед `coursesTaken` гэж байхгүй, тиймээс C1=байхгүй × C2 хослол утгагүй.
- Хичээл байхгүй үед `prerequisites` гэж байхгүй, тиймээс C3=байхгүй × C4 хослол утгагүй.
- `prerequisites: []` үед "зарим нь дутуу" / "огт үзээгүй" боломжгүй (хангах зүйл байхгүй).
- C5-ийн формат буруу (талбар дутуу, буруу JSON) үед C1–C4 хослол шалгагдах үе шатанд хүрэхгүй.

## Дүгнэлт

Дизайны 5 алхмаас хамгийн их бодол шаардсан нь 3 дахь алхам буюу төлөөлөх утгуудыг сонгох болон 4 дэх алхам буюу спецификац зохиох хэсэг байлаа. Учир нь сонголт бүрийн анги нь бусадтайгаа хослон нийт тестийн тоог хурдан нэмэгдүүлдэг тул аль хослол үнэхээр шинэ зүйл шалгаж байгааг ялгах шаардлагатай болсон. Боломжгүй хослолууд таарсан: оюутан байхгүй үед түүний coursesTaken гэж байхгүй, хичээл байхгүй үед prerequisites гэж байхгүй, мөн урьдач нөхцөл хоосон үед "зарим нь дутуу" гэх хослол утгагүй болно. Заавар нэг хүсэлтэд хоёр алдаа зэрэг байвал аль нь буцахыг заагаагүй тул давхар алдааны S11, S12 тестийг сервер дээр шалгаж тогтоосон. Үр дүнд нь оюутан байхгүй алдаа хичээл байхгүй алдаанаас түрүүлж, идэвхгүй оюутны алдаа урьдач нөхцөлийн алдаанаас түрүүлж буцдаг нь тогтоогдсон. Энэ нь серверийн согог биш, харин спецификацид тодорхойгүй орхигдсон зүйл гэдгийг тестүүд илрүүлсэн. Сервер асаалттай PASS ажиллуулалтад бүх 28 assertion амжилттай болсон тул энэ лабын хүрээнд серверийн хэрэгжилтэд заавартай зөрсөн согог олдоогүй. Туршилтын явцад миний өөрийн алдаа гарсан: /students/:id руу буруу метод (POST) явуулахад ERROR_NOT_FOUND буцсан нь серверийн бус миний хүсэлтийн алдаа байв. Тест бүр өөрийн setup-ыг өөрөө хийдэг тул бие даасан бөгөөд ажиллуулах дараалал нь үр дүнд нөлөөлөхгүй. Хэрэв дахин хийвэл registrationID-ийн яг утгыг шалгахгүй байх зарчмыг эхнээс нь баримтлах бөгөөд давхар алдааны дарааллыг ихэнх тохиолдолд (оюутан байхгүй + идэвхгүй гэх мэт) илүү олон хослолоор шалгана.
